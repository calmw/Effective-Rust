# Rust 常用函数：`copied()`、`cloned()` 与 `clone()`

在 Rust 中，从引用获得拥有所有权的值时，经常会遇到 `copied()`、`cloned()` 和 `clone()`。它们名字相近，但作用的对象和结果并不相同：

- `copied()`：把引用中的值复制出来，要求内部类型实现 `Copy`；
- `cloned()`：把引用中的值克隆出来，要求内部类型实现 `Clone`；
- `clone()`：克隆当前调用者本身，要求调用者的类型实现 `Clone`。

最常见的场景是把 `Option<&T>` 转换为 `Option<T>`，或者把产生 `&T` 的迭代器转换为产生 `T` 的迭代器。

## 1. 先理解 `Copy` 和 `Clone`

### 1.1 `Copy`：隐式、简单的值复制

实现了 `Copy` 的类型，在赋值或传参时不会失去原值的所有权，而是复制一份值：

```rust
let first = 42_u32;
let second = first;

assert_eq!(first, 42);  // first 仍然可用。
assert_eq!(second, 42);
```

整数、布尔值、字符、浮点数以及只包含 `Copy` 字段的部分结构体通常可以实现 `Copy`：

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

let first = Point { x: 10, y: 20 };
let second = first;

assert_eq!(first, second);
```

实现 `Copy` 的类型也必须实现 `Clone`。不过，`Copy` 不能为需要自定义析构逻辑的类型实现，包含 `String`、`Vec<T>` 等非 `Copy` 字段的结构体也不能直接实现 `Copy`。

### 1.2 `Clone`：显式创建副本

`Clone` 通过显式调用 `.clone()` 创建副本：

```rust
let first = String::from("Rust");
let second = first.clone();

assert_eq!(first, "Rust");
assert_eq!(second, "Rust");
```

如果写成 `let second = first;`，`String` 的所有权会移动到 `second`，之后不能再使用 `first`。调用 `clone()` 则会创建另一份独立拥有的字符串数据。

`Clone` 的成本取决于具体类型：

- 克隆 `String`、`Vec<T>` 通常需要分配内存并复制元素；
- 克隆 `Rc<T>` 或 `Arc<T>` 通常只增加引用计数；
- 克隆小型值类型可能非常便宜；
- 自定义类型可以在 `Clone::clone` 中执行自己的逻辑。

因此，不要简单地把 `clone()` 理解为必然昂贵，也不要假设它一定是“深拷贝”。应根据具体类型判断。

## 2. `copied()` 的用法

`copied()` 主要出现在 `Option<&T>` 和产生引用的迭代器上。它通过复制引用指向的值，把 `&T` 变成 `T`。

### 2.1 在 `Option<&T>` 上使用

```rust
let number = 42;
let borrowed: Option<&i32> = Some(&number);
let owned: Option<i32> = borrowed.copied();

assert_eq!(owned, Some(42));
assert_eq!(number, 42);
```

类型变化是：

```text
Option<&T> --copied()--> Option<T>
                         要求 T: Copy
```

它大致等价于：

```rust
let number = 42;
let borrowed = Some(&number);

let first = borrowed.copied();
let second = borrowed.map(|value| *value);

assert_eq!(first, second);
```

如果原值是 `None`，结果仍然是 `None`：

```rust
let borrowed: Option<&i32> = None;
assert_eq!(borrowed.copied(), None);
```

### 2.2 配合 `HashMap::get`

`HashMap::get` 返回 `Option<&V>`。当值实现了 `Copy` 时，`copied()` 可以直接取得 `Option<V>`：

```rust
use std::collections::HashMap;

let scores = HashMap::from([("Alice", 95), ("Bob", 88)]);

let alice_score: Option<i32> = scores.get("Alice").copied();
let carol_score: Option<i32> = scores.get("Carol").copied();

assert_eq!(alice_score, Some(95));
assert_eq!(carol_score, None);
```

如果只需要默认值，可以继续调用 `unwrap_or`：

```rust
use std::collections::HashMap;

let scores = HashMap::from([("Alice", 95)]);
let bob_score = scores.get("Bob").copied().unwrap_or(0);

assert_eq!(bob_score, 0);
```

### 2.3 在迭代器上使用

`Iterator::copied()` 把产生 `&T` 的迭代器转换为产生 `T` 的迭代器：

```rust
let numbers = vec![1, 2, 3];

let copied_numbers: Vec<i32> = numbers.iter().copied().collect();

assert_eq!(copied_numbers, vec![1, 2, 3]);
assert_eq!(numbers, vec![1, 2, 3]); // 原 Vec 只是被借用。
```

类型变化是：

```text
Iterator<Item = &T> --copied()--> Iterator<Item = T>
                                   要求 T: Copy
```

它大致等价于：

```rust
let numbers = [1, 2, 3];

let first: Vec<_> = numbers.iter().copied().collect();
let second: Vec<_> = numbers.iter().map(|value| *value).collect();

assert_eq!(first, second);
```

`copied()` 是惰性的：调用它只创建一个新的迭代器适配器；只有迭代器被消费时，元素才会逐个复制。

### 2.4 哪些类型不能使用 `copied()`

`String` 没有实现 `Copy`，所以下面的代码不能编译：

```rust,compile_fail
let names = vec![String::from("Alice"), String::from("Bob")];
let copied_names: Vec<String> = names.iter().copied().collect();
```

这是有意的限制：如果 `String` 能按位隐式复制，两份字符串会错误地认为自己拥有同一块堆内存。对于这类实现了 `Clone` 但没有实现 `Copy` 的类型，应根据需要使用 `cloned()`。

## 3. `cloned()` 的用法

`cloned()` 与 `copied()` 的形状相同，但它调用内部值的 `Clone::clone`，因此适用于更广泛的类型。

### 3.1 在 `Option<&T>` 上使用

```rust
let name = String::from("Alice");
let borrowed: Option<&String> = Some(&name);
let owned: Option<String> = borrowed.cloned();

assert_eq!(owned, Some(String::from("Alice")));
assert_eq!(name, "Alice");
```

类型变化是：

```text
Option<&T> --cloned()--> Option<T>
                         要求 T: Clone
```

它大致等价于：

```rust
let name = String::from("Alice");
let borrowed = Some(&name);

let first = borrowed.cloned();
let second = borrowed.map(Clone::clone);

assert_eq!(first, second);
```

### 3.2 配合 `HashMap::get`

当 `HashMap` 中的值是 `String`、`Vec<T>` 等非 `Copy` 类型，并且调用者确实需要拥有独立副本时，可以使用 `cloned()`：

```rust
use std::collections::HashMap;

let users = HashMap::from([
    (1_u64, String::from("Alice")),
    (2_u64, String::from("Bob")),
]);

let username: Option<String> = users.get(&1).cloned();

assert_eq!(username.as_deref(), Some("Alice"));
assert_eq!(users.get(&1).map(String::as_str), Some("Alice"));
```

如果只读取用户名，保留 `Option<&String>` 或使用 `as_deref()` 得到 `Option<&str>` 更高效：

```rust
use std::collections::HashMap;

let users = HashMap::from([(1_u64, String::from("Alice"))]);
let username: Option<&str> = users.get(&1).map(String::as_str);

assert_eq!(username, Some("Alice"));
```

不要因为借用类型看起来麻烦就习惯性调用 `cloned()`。克隆应该对应真正的所有权需求。

### 3.3 在迭代器上使用

```rust
let names = vec![String::from("Alice"), String::from("Bob")];

let cloned_names: Vec<String> = names.iter().cloned().collect();

assert_eq!(cloned_names, names);
assert_eq!(names.len(), 2); // 原 Vec 只是被借用。
```

类型变化是：

```text
Iterator<Item = &T> --cloned()--> Iterator<Item = T>
                                   要求 T: Clone
```

它大致等价于：

```rust
let names = vec![String::from("Alice"), String::from("Bob")];

let first: Vec<_> = names.iter().cloned().collect();
let second: Vec<_> = names.iter().map(Clone::clone).collect();

assert_eq!(first, second);
```

与 `copied()` 一样，迭代器上的 `cloned()` 也是惰性的。

### 3.4 `Copy` 类型也可以使用 `cloned()`，但优先用 `copied()`

因为 `Copy: Clone`，以下代码可以工作：

```rust
let numbers = [1, 2, 3];

let cloned: Vec<_> = numbers.iter().cloned().collect();
let copied: Vec<_> = numbers.iter().copied().collect();

assert_eq!(cloned, copied);
```

对于 `Copy` 类型，通常优先使用 `copied()`，因为它更准确地表达“这是简单的值复制”，也不会依赖某个可能存在自定义语义的显式克隆调用。

## 4. `clone()` 与 `cloned()` 的关键区别

这是最容易混淆的地方：

- `.clone()` 克隆调用者自身；
- `.cloned()` 克隆容器或迭代器中的被引用值。

### 4.1 `Option<&T>.clone()` 仍然保存引用

引用本身实现了 `Copy` 和 `Clone`。因此，对 `Option<&String>` 调用 `clone()`，克隆的是引用，而不是引用指向的 `String`：

```rust
let name = String::from("Alice");
let borrowed: Option<&String> = Some(&name);

let cloned_option: Option<&String> = borrowed.clone();
let cloned_value: Option<String> = borrowed.cloned();

assert_eq!(cloned_option, Some(&name));
assert_eq!(cloned_value, Some(String::from("Alice")));
```

类型对比：

```text
Option<&T>.clone()  -> Option<&T>  // 克隆 Option 和其中的引用
Option<&T>.cloned() -> Option<T>   // 克隆引用所指向的 T
Option<&T>.copied() -> Option<T>   // 复制引用所指向的 T，要求 T: Copy
```

### 4.2 `iterator.clone()` 克隆迭代器状态

对迭代器调用 `clone()` 通常会复制迭代器当前的位置，而不是把其中的元素克隆出来：

```rust
let numbers = [10, 20, 30];
let mut first_iterator = numbers.iter();

assert_eq!(first_iterator.next(), Some(&10));

let mut second_iterator = first_iterator.clone();

assert_eq!(first_iterator.next(), Some(&20));
assert_eq!(second_iterator.next(), Some(&20));
```

而 `iterator.cloned()` 是创建一个适配器，让后续产生的每个 `&T` 变成拥有所有权的 `T`。

### 4.3 克隆整个集合与克隆元素

```rust
let names = vec![String::from("Alice"), String::from("Bob")];

let whole_vector = names.clone();
let elements: Vec<_> = names.iter().cloned().collect();

assert_eq!(whole_vector, elements);
```

这个例子中结果相同，但表达的意图不同：

- `names.clone()` 明确表示复制整个 `Vec`；
- `names.iter().cloned()` 是迭代器流水线的一部分，可以继续接 `filter`、`take` 等操作，只克隆最终经过流水线的元素。

例如，只克隆满足条件的元素：

```rust
let names = vec![
    String::from("Alice"),
    String::from("Bob"),
    String::from("Alex"),
];

let names_starting_with_a: Vec<String> = names
    .iter()
    .filter(|name| name.starts_with('A'))
    .cloned()
    .collect();

assert_eq!(names_starting_with_a, vec!["Alice", "Alex"]);
```

这里先过滤再 `cloned()`，只有匹配的字符串会被克隆。如果先 `.cloned()` 再 `.filter(...)`，所有遍历到的字符串都会先被克隆。

## 5. 与 `into_iter()` 的区别

如果已经拥有一个集合，并且之后不再需要它，通常应通过 `into_iter()` 移动元素，而不是通过 `iter().cloned()` 复制元素：

```rust
let names = vec![String::from("Alice"), String::from("Bob")];

let owned_names: Vec<String> = names.into_iter().collect();

assert_eq!(owned_names, vec!["Alice", "Bob"]);
// names 已被消费，不能再使用。
```

三种方式的区别如下：

```text
values.iter()          -> 产生 &T，借用集合
values.iter().copied() -> 产生 T，借用集合并复制元素，要求 T: Copy
values.iter().cloned() -> 产生 T，借用集合并克隆元素，要求 T: Clone
values.into_iter()     -> 产生 T，消费集合并移动元素
```

选择原则：

- 只读取：使用 `iter()`，保留引用；
- 原集合还要使用，元素是 `Copy`：需要拥有值时使用 `copied()`；
- 原集合还要使用，元素只能 `Clone`：确实需要独立值时使用 `cloned()`；
- 原集合不再使用：优先使用 `into_iter()` 移动元素。

## 6. 引用层级带来的常见困惑

### 6.1 `Vec<&str>::iter()` 产生的是 `&&str`

集合元素本身如果已经是引用，调用 `iter()` 会再借用元素：

```rust
let names: Vec<&str> = vec!["Alice", "Bob"];

let mut iterator = names.iter();
let first: Option<&&str> = iterator.next();

assert_eq!(first, Some(&"Alice"));
```

此时 `.copied()` 去掉一层引用，得到 `&str`：

```rust
let names: Vec<&str> = vec!["Alice", "Bob"];
let copied: Vec<&str> = names.iter().copied().collect();

assert_eq!(copied, vec!["Alice", "Bob"]);
```

这里复制的是 `&str` 这个引用，不是克隆它指向的字符串内容。如果需要拥有的 `String`，必须显式创建：

```rust
let names: Vec<&str> = vec!["Alice", "Bob"];
let owned: Vec<String> = names.iter().map(|name| (*name).to_owned()).collect();

assert_eq!(owned, vec![String::from("Alice"), String::from("Bob")]);
```

### 6.2 `filter` 可能增加一层引用

许多迭代器适配器的闭包接收元素的引用。例如在 `Iterator<Item = &String>` 上调用 `filter`，闭包参数通常表现为 `&&String`，因为 `filter` 需要借用迭代项来判断是否保留。

Rust 的自动解引用让 `name.starts_with(...)` 等方法通常仍能直接调用。遇到类型不匹配时，可以先写出预期类型，逐层确认当前拿到的是 `T`、`&T` 还是 `&&T`，不要盲目增加 `clone()`。

## 7. 在泛型代码中使用

泛型函数可以通过 trait 约束明确需要复制还是克隆：

```rust
fn copy_option<T: Copy>(value: Option<&T>) -> Option<T> {
    value.copied()
}

fn clone_option<T: Clone>(value: Option<&T>) -> Option<T> {
    value.cloned()
}

let number = 42;
assert_eq!(copy_option(Some(&number)), Some(42));

let name = String::from("Alice");
assert_eq!(clone_option(Some(&name)), Some(String::from("Alice")));
```

不要为了能够调用 `copied()` 而随意给复杂类型实现 `Copy`。一个类型是否应该实现 `Copy` 是其所有权语义的一部分，而不仅是为了满足某段调用代码。

## 8. 性能与正确性建议

### 8.1 优先借用，按需取得所有权

如果后续操作只读取值，继续使用 `&T` 通常最清楚，也避免复制：

```rust
fn print_name(name: &str) {
    println!("{name}");
}

let name = Some(String::from("Alice"));

if let Some(value) = name.as_deref() {
    print_name(value);
}

assert!(name.is_some());
```

只有返回值必须独立存活、要跨越当前借用范围、要被存入拥有型容器或即将被修改时，才通常需要 `copied()` 或 `cloned()`。

### 8.2 不要用 `clone()` 绕过借用检查而不理解原因

克隆有时是合理解决方案，但如果只是看到借用错误就添加 `.clone()`，可能会：

- 隐藏不清晰的所有权设计；
- 在循环或热点路径产生大量分配；
- 复制本可借用的大型数据；
- 让数据副本之间出现不同步。

应先判断真正需要的是共享引用、移动所有权、共享所有权（如 `Arc<T>`），还是独立副本。

### 8.3 `Copy` 也不是完全没有成本

`copied()` 通常很便宜，但复制较大的数组或结构体仍然需要复制相应字节。类型实现了 `Copy` 不等于在任何热点路径中都可以忽略成本。性能敏感时应根据测量结果决定保留引用还是复制。

## 9. 常见错误清单

1. **对 `Vec<String>::iter()` 使用 `copied()`**：`String` 不是 `Copy`，需要所有权时使用 `cloned()`。
2. **把 `Option<&T>.clone()` 当成克隆内部值**：它通常仍得到 `Option<&T>`；要得到 `Option<T>` 使用 `cloned()`。
3. **已经拥有元素还调用 `cloned()`**：`cloned()` 面向引用；若集合不再使用，考虑 `into_iter()`。
4. **只读取却复制数据**：能使用 `&T` 或 `&str` 时优先借用。
5. **不区分复制引用和复制数据**：对 `&&str` 使用 `copied()` 得到的是 `&str`，不是 `String`。
6. **认为所有 `clone()` 都是深拷贝或都很昂贵**：成本和语义由具体类型决定。
7. **先克隆再过滤**：迭代器中通常先过滤，再克隆最终需要的元素。
8. **用克隆掩盖所有权设计问题**：先明确数据应该由谁拥有以及需要存活多久。

## 10. 一个完整示例

下面的例子同时展示 `copied()`、`cloned()`、借用和 `into_iter()` 的合理使用：

```rust
use std::collections::HashMap;

#[derive(Debug, Clone, PartialEq, Eq)]
struct User {
    name: String,
    active: bool,
}

fn main() {
    let limits = HashMap::from([("requests", 100_u32)]);
    let users = HashMap::from([
        (
            1_u64,
            User {
                name: String::from("Alice"),
                active: true,
            },
        ),
        (
            2_u64,
            User {
                name: String::from("Bob"),
                active: false,
            },
        ),
    ]);

    // u32: Copy，取得独立数值时使用 copied()。
    let request_limit: u32 = limits.get("requests").copied().unwrap_or(0);
    assert_eq!(request_limit, 100);

    // 只读取用户名：保留借用，不克隆 User 或 String。
    let first_name: Option<&str> = users.get(&1).map(|user| user.name.as_str());
    assert_eq!(first_name, Some("Alice"));

    // 确实需要一份可独立修改的用户数据时才使用 cloned()。
    let mut editable_user: User = users.get(&1).cloned().expect("用户 1 应当存在");
    editable_user.name.push_str(" Chen");

    assert_eq!(editable_user.name, "Alice Chen");
    assert_eq!(users.get(&1).unwrap().name, "Alice");

    // 集合不再使用时，into_iter() 直接移动元素，不进行克隆。
    let active_users: Vec<User> = users
        .into_iter()
        .map(|(_id, user)| user)
        .filter(|user| user.active)
        .collect();

    assert_eq!(active_users.len(), 1);
    assert_eq!(active_users[0].name, "Alice");
}
```

## 总结

可以用下面的规则快速选择：

```text
当前有 &T，只想读取                 -> 保留 &T
当前有 &T，需要 T，且 T: Copy       -> copied()
当前有 &T，需要 T，且 T: Clone      -> cloned()
要复制当前值或整个容器               -> clone()
已经拥有集合且不再需要它             -> into_iter() 移动元素
```

最重要的区别是：`clone()` 操作当前调用者，`cloned()` 和 `copied()` 则用于把被引用的内部元素转换为拥有所有权的值。先明确是否真的需要所有权，再选择相应方法，可以让 Rust 代码既清晰又高效。
