# Rust 语法解释：闭包中的 `|...|`

观察下面两段代码：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();
let key = "timeout";
let value = map.entry(key).or_insert_with(|| 30);

assert_eq!(*value, 30);
```

```rust
use std::collections::HashMap;

let mut lengths = HashMap::new();
lengths
    .entry(String::from("hello"))
    .or_insert_with_key(|key| key.len());

assert_eq!(lengths.get("hello"), Some(&5));
```

这里的竖线 `|` 用来定义 **闭包（closure）** 的参数列表：

- `|| 30`：一个没有参数、返回 `30` 的闭包；
- `|key| key.len()`：一个接收参数 `key`、返回 `key.len()` 的闭包。

闭包类似于可以写在表达式中的匿名函数。

## 1. 闭包的基本语法

闭包的一般形式是：

```text
|参数1, 参数2, ...| 表达式
```

例如：

```rust
let add = |left, right| left + right;

assert_eq!(add(2, 3), 5);
```

两个 `|` 之间是参数列表，后面的表达式是闭包体：

```text
|left, right| left + right
 └────┬────┘  └─────┬─────┘
     参数列表          闭包体
```

闭包没有参数时，两个竖线之间为空：

```rust
let answer = || 42;

assert_eq!(answer(), 42);
```

闭包有一个参数时：

```rust
let double = |number| number * 2;

assert_eq!(double(5), 10);
```

闭包有多个参数时，使用逗号分隔：

```rust
let multiply = |left, right| left * right;

assert_eq!(multiply(4, 5), 20);
```

## 2. 第一段代码中的 `|| 30`

原代码是：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();
let key = "timeout";
let value = map.entry(key).or_insert_with(|| 30);

assert_eq!(*value, 30);
```

其中：

```rust
let create_default = || 30;
assert_eq!(create_default(), 30);
```

`|| 30` 可以分为两部分：

```text
||       30
│        └── 闭包的返回值
└─────────── 空参数列表，表示不接收参数
```

因此，下面两种写法表达相同的默认值计算逻辑：

```rust
fn default_timeout() -> i32 {
    30
}

let closure_result = (|| 30)();
let function_result = default_timeout();

assert_eq!(closure_result, function_result);
```

在 `or_insert_with` 中，传入的是闭包本身，而不是立即计算出的 `30`：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();

map.entry("timeout").or_insert_with(|| 30);
```

它也可以改写成命名函数：

```rust
use std::collections::HashMap;

fn default_timeout() -> i32 {
    30
}

let mut map = HashMap::new();
map.entry("timeout").or_insert_with(default_timeout);

assert_eq!(map.get("timeout"), Some(&30));
```

注意传递的是 `default_timeout`，没有写调用括号。`default_timeout()` 表示立即调用函数并得到数值，而 `default_timeout` 表示把函数交给 `or_insert_with`，由它在需要时调用。

### 2.1 为什么要传闭包

`or_insert_with` 只在键不存在时调用闭包并生成默认值。如果键已经存在，闭包不会执行：

```rust
use std::collections::HashMap;

let mut map = HashMap::from([("timeout", 60)]);
let mut call_count = 0;

let value = map.entry("timeout").or_insert_with(|| {
    call_count += 1;
    30
});

assert_eq!(*value, 60);
assert_eq!(call_count, 0);
```

这叫作**惰性求值**。如果默认值需要分配内存、读取配置或执行复杂计算，只有真正缺少键时才计算会更加高效。

相比之下，`or_insert` 直接接收一个已经构造好的值：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();
map.entry("timeout").or_insert(30);

assert_eq!(map.get("timeout"), Some(&30));
```

选择原则：

- 默认值简单且构造成本很低：使用 `or_insert(value)`；
- 默认值构造昂贵或有副作用：使用 `or_insert_with(|| value)`；
- 类型的默认值正好满足需求：使用 `or_default()`。

```rust
use std::collections::HashMap;

let mut counters: HashMap<&str, usize> = HashMap::new();
*counters.entry("requests").or_default() += 1;

assert_eq!(counters.get("requests"), Some(&1));
```

## 3. 第二段代码中的 `|key| key.len()`

原代码是：

```rust
use std::collections::HashMap;

let mut lengths = HashMap::new();
lengths
    .entry(String::from("hello"))
    .or_insert_with_key(|key| key.len());

assert_eq!(lengths.get("hello"), Some(&5));
```

闭包部分是：

```text
|key|       key.len()
  │             └── 闭包体：计算 key 的长度并返回 usize
  └──────────────── 参数：对即将插入的键的引用
```

`or_insert_with_key` 会在键不存在时，把键的引用传给闭包。这里编译器推断出的闭包参数类型是 `&String`：

```rust
let key_length = |key: &String| -> usize { key.len() };

assert_eq!(key_length(&String::from("hello")), 5);
```

完整写出类型后，下面两种闭包等价：

```rust
let short = |key: &String| key.len();
let full = |key: &String| -> usize { key.len() };

let key = String::from("hello");
assert_eq!(short(&key), full(&key));
```

Rust 通常能从 `or_insert_with_key` 的方法签名推断参数和返回值类型，因此惯用写法会省略类型标注。

### 3.1 为什么闭包能获得键

可以将 `or_insert_with_key` 的核心签名简化理解为：

```text
or_insert_with_key(F) -> &mut V
其中 F: FnOnce(&K) -> V
```

对于这段代码：

```text
K = String
V = usize
F 接收 &String，返回 usize
```

因此 `|key| key.len()` 正好满足要求：

```text
&String -> usize
```

键 `"hello"` 不存在时，闭包接收到它的引用，计算长度 `5`，随后映射中插入：

```text
"hello" -> 5
```

这种设计允许默认值依赖于键本身，并且不需要为了计算默认值额外克隆键。

### 3.2 等价的命名函数写法

```rust
use std::collections::HashMap;

fn string_length(key: &String) -> usize {
    key.len()
}

let mut lengths = HashMap::new();
lengths
    .entry(String::from("hello"))
    .or_insert_with_key(string_length);

assert_eq!(lengths.get("hello"), Some(&5));
```

简单逻辑使用闭包通常更紧凑；逻辑较长、需要复用或值得单独测试时，可以使用命名函数。

### 3.3 `key.len()` 返回的是字节数

`String::len()` 返回 UTF-8 字节数，而不是用户看到的字符数量：

```rust
use std::collections::HashMap;

let mut byte_lengths = HashMap::new();
byte_lengths
    .entry(String::from("你好"))
    .or_insert_with_key(|key| key.len());

assert_eq!(byte_lengths.get("你好"), Some(&6));
```

如果需要统计 Unicode 标量值数量，应使用 `chars().count()`：

```rust
use std::collections::HashMap;

let mut character_counts = HashMap::new();
character_counts
    .entry(String::from("你好"))
    .or_insert_with_key(|key| key.chars().count());

assert_eq!(character_counts.get("你好"), Some(&2));
```

## 4. 闭包体可以包含多条语句

只有一个表达式时可以直接写：

```rust
let square = |number| number * number;
assert_eq!(square(4), 16);
```

有多条语句时使用花括号：

```rust
let calculate = |number: i32| {
    let doubled = number * 2;
    doubled + 1
};

assert_eq!(calculate(5), 11);
```

最后一个没有分号的表达式是闭包返回值。如果加上分号，返回值会变成单元类型 `()`：

```rust
let returns_number = || {
    30
};

let returns_unit = || {
    30;
};

assert_eq!(returns_number(), 30);
assert_eq!(returns_unit(), ());
```

这与普通函数体的返回规则相同。

## 5. 闭包可以捕获周围环境

闭包与普通函数的重要区别之一，是闭包可以使用定义位置周围的变量：

```rust
let base = 20;
let add_base = |number| base + number;

assert_eq!(add_base(10), 30);
```

这里的 `base` 没有作为参数传入，而是被闭包从环境中捕获。

在 `or_insert_with` 中，默认值可以来自外部配置：

```rust
use std::collections::HashMap;

let configured_timeout = 45;
let mut map = HashMap::new();

map.entry("timeout")
    .or_insert_with(|| configured_timeout);

assert_eq!(map.get("timeout"), Some(&45));
```

编译器会根据闭包如何使用捕获的变量，自动决定通过以下哪种方式捕获：

- 不可变借用；
- 可变借用；
- 取得所有权。

### 5.1 捕获不可变引用

```rust
let prefix = String::from("Hello");
let greet = |name: &str| format!("{prefix}, {name}");

assert_eq!(greet("Alice"), "Hello, Alice");
assert_eq!(prefix, "Hello");
```

### 5.2 捕获可变引用

```rust
let mut count = 0;

let mut increment = || {
    count += 1;
};

increment();
increment();
drop(increment); // 结束闭包对 count 的可变借用。

assert_eq!(count, 2);
```

### 5.3 使用 `move` 取得所有权

`move` 会要求闭包取得所捕获变量的所有权，在线程或需要闭包独立存活时很常见：

```rust
let message = String::from("hello from worker");

let worker = std::thread::spawn(move || {
    assert_eq!(message, "hello from worker");
});

worker.join().expect("worker should finish");
```

`move || { ... }` 中的 `||` 仍然是闭包的空参数列表；`move` 只改变捕获环境变量的方式。

## 6. `Fn`、`FnMut` 和 `FnOnce`

闭包会根据它如何使用捕获值，自动实现一个或多个调用 trait：

- `Fn`：可以通过共享引用重复调用，不修改或消费捕获值；
- `FnMut`：调用时可能修改捕获值，需要可变访问；
- `FnOnce`：至少能调用一次，调用时可能消费捕获值。

`or_insert_with` 和 `or_insert_with_key` 只需要在键缺失时调用一次闭包，因此它们接受 `FnOnce`：

```text
or_insert_with:     FnOnce() -> V
or_insert_with_key: FnOnce(&K) -> V
```

这也意味着闭包可以把捕获的值移动到 `HashMap` 中：

```rust
use std::collections::HashMap;

let default_value = String::from("30 seconds");
let mut map = HashMap::new();

map.entry("timeout")
    .or_insert_with(|| default_value);

assert_eq!(map.get("timeout").map(String::as_str), Some("30 seconds"));
```

这里闭包执行时会消费 `default_value`，所以它不能作为同一个闭包被重复执行。通常不需要手写 `Fn`、`FnMut` 或 `FnOnce`；理解 API 的 trait 约束有助于解释所有权和编译错误。

## 7. `value` 为什么要写成 `*value`

第一段代码中：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();
let value = map.entry("timeout").or_insert_with(|| 30);

assert_eq!(*value, 30);
```

`or_insert_with` 返回的是映射中值的可变引用 `&mut V`。在这个例子中：

```text
V              = i32
value 的类型    = &mut i32
*value 的类型   = i32
```

`*` 是解引用运算符，用来访问引用指向的值。由于得到的是可变引用，还可以直接修改映射中的数据：

```rust
use std::collections::HashMap;

let mut map = HashMap::new();
let value = map.entry("timeout").or_insert_with(|| 30);
*value += 5;

assert_eq!(map.get("timeout"), Some(&35));
```

词频统计中的惯用写法也是同一个原理：

```rust
use std::collections::HashMap;

let mut counts = HashMap::new();

for word in ["rust", "safe", "rust"] {
    *counts.entry(word).or_insert(0) += 1;
}

assert_eq!(counts.get("rust"), Some(&2));
```

## 8. `|` 和 `||` 在其他位置的含义

竖线并不总是闭包语法，需要根据上下文判断。

### 8.1 `||` 也可以表示逻辑或

```rust
let is_admin = false;
let is_owner = true;

assert!(is_admin || is_owner);
```

区别是：

```text
|| 30                 无参数闭包，产生一个可以调用的值
left || right         布尔逻辑或
```

逻辑或的 `||` 位于两个布尔表达式之间；闭包的 `||` 位于闭包表达式开头，表示空参数列表。

### 8.2 单个 `|` 可以表示按位或

```rust
let flags = 0b0101_u8 | 0b0011_u8;
assert_eq!(flags, 0b0111_u8);
```

这里 `|` 位于两个数值表达式之间，表示按位或，不是闭包参数边界。

### 8.3 单个 `|` 可以表示“或模式”

```rust
fn is_weekend(day: u8) -> bool {
    matches!(day, 6 | 7)
}

assert!(is_weekend(6));
assert!(is_weekend(7));
assert!(!is_weekend(1));
```

模式中的 `6 | 7` 表示匹配 `6` 或 `7`。

## 9. 两段代码的执行过程

### 9.1 `or_insert_with(|| 30)`

```text
调用 map.entry("timeout")
          │
          ├─ 键已经存在 ──> 返回现有值的 &mut 引用，不调用闭包
          │
          └─ 键不存在 ────> 调用 || 30
                                  │
                                  └─ 返回 30，将它插入 HashMap
                                             │
                                             └─ 返回新值的 &mut 引用
```

### 9.2 `or_insert_with_key(|key| key.len())`

```text
调用 lengths.entry(String::from("hello"))
          │
          ├─ 键已经存在 ──> 返回现有值的 &mut 引用，不调用闭包
          │
          └─ 键不存在 ────> 将 &String 传给 |key| key.len()
                                      │
                                      └─ 计算 5，将它作为值插入
                                                   │
                                                   └─ 得到 "hello" -> 5
```

二者最关键的区别是闭包参数：

```text
or_insert_with(|| value)              闭包没有参数
or_insert_with_key(|key| make(key))   闭包接收键的引用
```

## 10. 常见错误

### 10.1 把闭包参数的竖线写成括号

Rust 闭包使用 `|parameter|`，而不是 JavaScript 风格的 `(parameter) =>`：

```rust
let length = |text: &str| text.len();
assert_eq!(length("Rust"), 4);
```

### 10.2 混淆传递闭包与调用闭包

```rust
let make_value = || 30;

let closure = make_value; // 传递闭包本身。
let value = closure();    // 使用 () 调用闭包。

assert_eq!(value, 30);
```

`or_insert_with` 需要接收闭包本身，因此写 `or_insert_with(|| 30)`。方法会在需要时替你调用它。

### 10.3 在闭包返回表达式后误加分号

```rust,compile_fail
use std::collections::HashMap;

let mut map: HashMap<&str, i32> = HashMap::new();

map.entry("timeout").or_insert_with(|| {
    30; // 分号让闭包返回 ()，但映射需要 i32。
});
```

正确写法是让最后的 `30` 不带分号：

```rust
use std::collections::HashMap;

let mut map: HashMap<&str, i32> = HashMap::new();

map.entry("timeout").or_insert_with(|| {
    30
});

assert_eq!(map.get("timeout"), Some(&30));
```

### 10.4 默认值依赖键却额外克隆键

如果默认值依赖即将插入的键，优先使用 `or_insert_with_key` 提供的 `&K`，而不是在外部额外保留或克隆一份键。

### 10.5 以为闭包一定会执行

`or_insert_with` 和 `or_insert_with_key` 只在键不存在时调用闭包。如果某项操作必须无条件执行，不应把它放进这些默认值闭包中。

## 总结

两段代码中的 `|` 都属于闭包语法：

```rust
let no_parameter = || 30;
let one_parameter = |key: &String| key.len();

assert_eq!(no_parameter(), 30);
assert_eq!(one_parameter(&String::from("hello")), 5);
```

可以这样记忆：

```text
|| expression            无参数闭包
|x| expression           一个参数的闭包
|x, y| expression        多个参数的闭包
|x| { statements }       包含多条语句的闭包
move |x| expression      取得环境变量所有权的闭包
```

在 `HashMap::entry` API 中，闭包用于延迟生成默认值：`or_insert_with` 的闭包不接收参数，`or_insert_with_key` 的闭包接收键的引用。键已经存在时，两者都不会执行闭包。
